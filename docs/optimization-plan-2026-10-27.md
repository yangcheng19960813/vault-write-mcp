# VaultWrite 优化计划（2026-10-27）

状态：**提案，尚未实施。** 本计划整理自当前项目基线与本次只读审计；项目变更记录见 [`CHANGELOG.md`](../CHANGELOG.md)。以下优先级、范围与验收条件供确认后拆分工作，不代表已授权实现、合并或发布。本计划不扩展为 QMD 集成，不削弱版本校验，也不自动选择 ours/theirs。

## P1｜补齐可靠性与写入边界

### 1. 将 push 检查点绑定到 remote 身份

- **目标：** 避免同名 remote 的 URL 改变后错误跳过推送。已知复现场景位于 `src/vault_write_mcp/batch.py:163–167`：HEAD 不变而 `origin` 改指新远端。
- **建议范围：** 检查点纳入 Git 实际使用的 push URL（可能有多个 `pushurl`，不可用 fetch URL 替代）及目标分支；规范化后仅保存单向摘要，不持久化或输出 URL/凭据。
- **验收：** 相同 remote/HEAD 不重复推送；URL 或目标变化触发安全推送检查；失败可重试且保留正确检查点；日志、状态文件和错误信息均不泄漏凭据。
- **风险：** URL 规范化可能误判同一远端，需明确 SSH/HTTPS 形式及凭据差异处理。

### 2. 统一写入允许/拒绝规则

- **目标：** 保护策略不能被某一种写入入口绕过。
- **建议范围：** 可配置策略一致作用于 `write`、`append`、`patch`、`move`，包括移动后所有受影响引用文件。`actor` 是调用方提供的审计标签，不是认证身份。默认保持当前行为，保护策略须显式配置。
- **验收：** 逐工具测试允许/拒绝、预览和执行一致性、拒绝时零部分写入及旧配置默认兼容；明确路径规范化、移动跨策略边界和请求重放语义。
- **风险：** 策略不一致会形成旁路；新增限制也可能意外阻塞既有工作流。

### 3. 为 `find_note` 增加可选紧凑上下文

- **目标：** 避免同一行在命中列表与窗口中重复占用响应预算，同时保持命中定位可靠。
- **建议范围：** 仅新增 opt-in 紧凑模式，以窗口原样返回文本、用行号/索引引用匹配；不做有损摘要或文本压缩。默认响应形状、匹配分页、字节/行硬上限均不变。
- **验收：** 覆盖重复命中、长行、重叠窗口、分页、截断和边界参数，与默认模式逐项比较；确认原文及锚点完整保留。用固定数据报告序列化 JSON 与可测得的实际传输字节数；这些指标不是模型 token 数。实际客户端 token 计量可作为单独可选数据，不推算或编造节省比例。
- **风险：** 新响应形状可能被调用方误读；不得放宽锚点或版本校验。

### 4. 只读诊断和可选历史辅助

- **目标：** 让操作者理解笔记历史及未完成事务状态，避免诊断动作扩大损害。
- **建议范围：** `note_history` 可提供 opt-in 的重命名关联，基于 Git 相似度仅作启发式；新增只读 doctor/recovery 诊断，说明事务状态、恢复条件及人工下一步。诊断不得经由 `VaultStore` 当前初始化/恢复路径（构造期间的 `_recover` 可能修改数据）；应能在损坏状态下安全检查，并输出脱敏且有界的信息。
- **验收：** 测试相似文件误关联、损坏/未完成日志诊断；通过故障注入证明 doctor 不触发恢复、不写文件、不改 Git 状态，并对敏感字段脱敏、限制输出大小。
- **风险与边界：** Git rename 推断不保证正确；不自动选择冲突一方，也不自动删除事务日志。

## 后续候选（P1 完成后再评估）

- **性能：** 独立评估 `git cat-file` 批量读取、后缀索引与有界路径发现。先建立大库基准；只有在版本保护、路径约束与结果一致性均有证据时再采用。
- **模型调用延迟：** 模型功能本身继续默认关闭；若启用模型，则应有不可被分阶段读写超时延长的硬总时限，并评估生成期间释放写锁、重入时重新校验。超时/并发验收须证明不会重复提交、丢写或过期覆盖。
- **低优先级恢复：** 专项检查事务中断后的 chmod/权限恢复不变量，补充可复现故障注入及跨平台验收。
